# ショート動画の計画（2026-10-27〜）

まじゃすこの広報用の縦型ショート動画（1080×1920・15〜30秒）。**1本の動画を YouTube ショート・TikTok・Instagram リール に同じものを出す**。
目的は、アプリの告知だけでなく、**アカウントそのものの再生数とエンゲージメント（保存・コメント・シェア）を上げる**こと。
そのため、アプリの話をしない回（あるある・ニッチ・初心者の壁）も混ぜ、最後の数秒だけ自然にアプリへつなぐ。

## 作り方
- `python tools/make_short.py [名前]` → `まじゃすこ素材/video/<名前>.mp4`（本体リポジトリには入れない。素材の privateリポジトリにコミットする）
- HTMLの1コマずつを時刻を進めながら撮って、ffmpeg でつなぐ（録画ではないので毎回同じ仕上がり）。要: `pip install imageio-ffmpeg`
- 見た目は tools/make_sns_v3.py と共通（淡い緑の地・本物の画面のスマホ・数字のカード・✨）。画面は assets/screens/ のスクショ
- 台本は make_short.py の `VIDEOS` に関数を1つ足す。要素は `at(出る秒, 消える秒, 中身)`、スマホは `phone_at`、数字のカードは `chip_at`、最後は `end_card`
- **ナレーションと字幕の型**（2026-11-04・ユーザーの理想に近い形・`python tools/make_narrated.py [名前]`）: 見た目は make_short.py のまま、声の長さから場面の時刻を決める。声は男性の自然な声（edge-tts・ja-JP-KeitaNeural・+12%）、**字幕は声に合わせて、動画のカードと同じ白い丸の帯に濃い文字で出す。語尾の「、」「。」は付けない（2026-11-05 ユーザーの判断。白文字に黒縁は動画の雰囲気に合わない）。VOICEVOXのクレジットは字幕と重ならない y=1700。位置はスマホの下の y=1500（下の約300pxに入らない）。1区切り16文字以内・語の途中で折らない。スマホは幅520pxのまま小さくしない**（見出しを上へ寄せ、スマホを y=400 に置いて、字幕の場所を作る。2026-11-04 ユーザーの指定）、BGMは自作で控えめ。無理なカットインは増やさない。要: `pip install edge-tts truststore`。edge-tts は非公式の使い方なので、公開の前に利用条件を確かめる
- **出すのは声入りの版**（2026-11-05 ユーザーの判断: すべての動画にずんだもんの声と字幕）。`python tools/make_narrated.py --vv 3 ずんだもん zundamon` で全部 → `voice-<名前>-zundamon.mp4`（名前を付けると1本だけ）。
  場面で組む動画（kinou・aruaru-shukei・kabe-umaoka）は make_narrated.py の `NARR` に台本と場面を持ち、声の長さで場面の時刻が決まる。
  録画の動画（play-*・calc-vs・nakama-*・mypage-*）は `TIMED` に「録画の目印 → 声」を書き、make_short.py の動画を `NARR=True`（スマホを y=400・幅520 に上げ、見出しの下のひとことを消す・フックの長さを声に合わせる）で作って声を重ねる。
  nakama-*・mypage-* は台本を書いていなければ make_short.py の字幕をそのまま声にする。声が前の声にぶつかって0.6秒以上おくれると「！声が…おくれる」と出るので、台本を短くする
- 声は VOICEVOX も使える: エンジン（run.exe）を動かして `python tools/make_narrated.py kinou --vv <話者ID> <クレジットの名前> [出力名]`。話者IDは http://127.0.0.1:50021/speakers。動画に `VOICEVOX:名前` のクレジットが入る。音声の作業はユーザーが家のPCで行う（2026-11-04。会社PCではエンジンの起動が権限で止まった）。声の調子は「元気に」・採用はずんだもん（3）と春日部つむぎ（8）（2026-11-05 ユーザーの判断）
- 外の曲は動画に焼き込まない（著作権の都合）。音ありは `tools/make_hype.py` だけで、BGM・効果音は numpy で自作、声は Windows の音声合成（Microsoft Haruka）。make_short.py の動画は音なし
- **テンポの速い型**（2026-11-04・`python tools/make_hype.py [名前]`）: 150BPM・1.6秒ごとに切り替え・文字を叩きつけて画面をゆらす・地の色を毎回変える・全体15秒前後。台本は make_hype.py の `HYPE` に足す。スマホの部品は `.bar` などの素直なクラス名を使っているので、足すCSSは `hy-` を付ける（ぶつかるとノッチが左へ寄った）
- 文字は画面の上〜中央に置く。**下の約300pxと右端の約150pxは、いいね・コメントのボタンと説明文に隠れる**
- 用語ルール（CLAUDE.md）は動画の字幕にも効く（金銭を連想させる語は禁止・「スコア記録」）

## 2026-11-06の決まり（ユーザーの指摘）
- **文字だけの動画は出さない**。牌・卓の絵・本物の画面・数字の動きを必ず入れる。台本と部品は `tools/video_topics.py`、ネタは docs/video-topics.md
- **冒頭＝サムネ**（札＋題名＋絵）。`-thumb.jpg` は冒頭の画面から字幕を外したもの。地の色・字・絵の位置はそろえる
- **白いカードは文字の説明・表・式・棒グラフだけ**（2026-11-09 ユーザーの選択＝中間の案）。牌・イラスト・写真は地の上にそのまま置き、薄い影で浮かせる（`video_topics.py` の `.vcard:not(:has(...))`）
- 字幕は必ず画面の中央。`make_short.build` が幅を確かめ、はみ出す字幕は字を小さくし、中央でなければ止まる
- 録画と画面の高さは 390×792（スマホの枠と同じ比率）。844だと下が切れて右下のオレンジのボタンが欠ける
- **録画（まじゃすこ素材/video/clips/）はすべて素材リポジトリにコミットする**（2026-11-06 ユーザーの判断。録画したPCと声を入れるPCが違っても作れるように）。
  仲間ページ・マイページの10本（nakama-*・mypage-*）の録画は `python tools/record_play.py nakama-rank --data まじゃすこ素材/data/circle_anon.json`（どのPCでも撮れる）
- 会社PCは声なしの下書きまで: `python tools/make_narrated.py --draft` → `voice-<名前>-draft.mp4`。声は個人PCで `python tools/make_narrated.py --vv 3 ずんだもん zundamon`

- 団体ルールの比較は Mリーグを基準に、確かめられた団体だけを並べる（確かめた先は `video_topics_ml.py` の先頭）
- 役シリーズ（`tools/video_topics_yaku.py`）: y-01 リーチ・y-03 ピンフ・y-05 役牌は条件とダメな例・門前と鳴いた例まで説明する長い版。似ている役は2つ並べる（y-07 三色と一通・y-09 チャンタと純チャン・y-11 三暗刻と四暗刻）。相手の y-08・y-17・y-21 は外した

## 1本の型（どの種類も共通）
1. **0〜2.5秒＝フック**：大きな文字1つで「自分のことだ」と思わせる（問いかけ・言い切り・数字）。ロゴや挨拶から始めない
2. **本編**：1画面に言いたいことは1つ。3〜4秒ごとに画面を切り替える（止まると離脱される）
3. **最後の4秒＝まじゃすこ**：ロゴ・majasco.jp・「プロフィールのリンクから」。アプリと関係ない回でも必ず付ける
- 長さは15〜30秒。最後まで見られた割合が伸びるので、迷ったら短く

## 4つの柱（ローテーション）
| 柱 | 狙い | 例 |
|---|---|---|
| A 正面から機能・告知 | 使ってみたい人を増やす | 「麻雀の集計、まだ電卓？」・新機能の告知・仲間ページ |
| B あるある（コア層） | 共感→コメント・シェア | 集計係あるある・セット麻雀の夜あるある・三麻派あるある |
| C ニッチ・ストレス | 「わかる」「知らなかった」→保存 | 点数申告で揉める・ローカルルールの違い・チップの数え方 |
| D 初心者の壁 | 保存・フォロー（あとで見返す） | ウマ・オカ・符計算の入口・役の覚え方・点数の数え方 |
- フックの型：「〜してる人、損してます」は使わない（煽りすぎ）。使う型＝**問いかけ**（まだ電卓？）／**数字**（20秒でわかる）／**あるある宣言**（集計係あるある）／**意外**（実はウマは決まってない）
- コメントを呼ぶ終わり方：B・Cは最後に「あなたの卓はどっち？」のような問いを1行入れる

## 操作している画面の動画（2026-10-27〜）
- `python tools/record_play.py [名前]` → アプリ（スタブ・本番に触れない）を台本どおりにタップ・入力しながら画面を撮る。
  出力 `まじゃすこ素材/video/clips/<名前>/`（コマのJPEGと timeline.json）。台本は record_play.py の `PLAYS` に関数を足す
  （`r.tap(セレクタ)`・`r.type(セレクタ, 文字)`・`r.swipe(px)`・`r.idle(秒)`・`r.mark(名前)`）
- 指と、タップのオレンジの波紋は**録画には描かない**。make_short.py の `live_at(出る秒, 消える秒, 録画名)` が30コマ/秒で重ねる
  （画面の録画は1秒に9〜11コマしか撮れないが、指はなめらかに動く）。指は動かしている間とタップの前後だけ出て、止まると消える
- 字幕は録画の `r.mark()` の時刻に合わせる（`m["input"]` など）。**字幕と画面の中身が合っているか必ずコマで確かめる**
  （2026-10-27: 4試合目で順位が変わらないのに「入れかわる」と書いていた → 点数を変えて美咲が逆転するようにした）
- 見本の名前は 健太・美咲・翔・陽菜。仮の名前（A〜D）は録画の中でゲームの設定を書きかえて変える
- **仲間ページ・マイページの録画**は、実際の仲間ページの数字（名前は置きかえ済み・リポジトリに入れない）を `--data <circle_anon.json>` で渡す（shoot_lp_screens.py と同じデータ）。
  `python tools/record_play.py nakama-rank --data <json>`。押せる所を調べるときは `explore`。大会名（元の仲間の名前が入っている）は「夏のリーグ戦」「秋の大会」に置きかえる
- 台本の作り方：`PAGE_VIDEOS`（make_short.py）に「録画名: (ラベル, 冒頭の一言, [(録画の目印, 字幕)…])」を1行足すだけで動画になる

## 落とし穴
- 用語・役・Mリーグの台本は VOICEVOX の読み違いが多い（流局→ナガレキョク・面子→メンコ・刻子→コクコ・翻→コボシ・雀魂→スズメタマシイ・一・九→イッテンキュウ・選手名など）。声を作る前に、台本の全部の文を audio_query に通して読みを出し、別の読み（pykakasi）と違う所を見て `SAY` に足す（2026-11-09。`SAY` は長い語から置きかえる＝「大明槓」が「槓」より先）
- 字幕の箱（.sub）は左右の余白をそろえる（left・right とも60px）。右だけ広くすると字幕が中心より左に寄る（2026-11-05 ユーザーの指摘）
- VOICEVOX は「麻雀」を マアジャン＼ノ、「集計」を シュウケ＼エ、「無料」を ムリョオ＼デ と読み、ユーザー辞書（優先度10でも）では直らなかった。make_narrated.py の `VV_ACCENT`（読みの頭 → 下がる位置。0=平板）で audio_query の後に直す。辞書の語（`VV_WORDS`）もエンジンのPCにしか残らないので毎回コードから入れる。変な読みが見つかったら両方に足す
- 牌や用語の読みは VOICEVOX がよく外す（萬子→ヨロズコ・筒子→トンズ・王牌→オオパイ・安パイ→ヤスパイ・「白・發・中」の發を読まない）。新しい台本は声を作る前に make_narrated.py の vv_query でアクセント句を出して読みを確かめ、外れたら `SAY` に足す（2026-11-06）
- bashのヒアドキュメントから台本の文字列を置きかえると、`\n` の扱いで一致しないことがある → Edit で直す（2026-10-27）
- ✨は字幕の行の右端に置かない（文字にかぶる）。sparkles() の位置は字幕が出る上の帯（y 200〜420）を避ける
