# ブログ仕様・記事運用

## 構成
- カテゴリ: `/mahjong/`（麻雀攻略）・`/news/`（お知らせ）・`/blog/`（雑記）。`blog.html`=全記事一覧
- **既存記事のURL（ルート直下のblog-*.html）は変えない**（インデックス維持）。お知らせだけ `/news/xxx.html`
- 記事メタは `/assets/blog-site.js` の **BLOG_POSTS で一元管理**（url/cat/date/tag/title/desc/recommended）。
  一覧・カテゴリ・サイドバー・カテゴリナビはここから自動描画
- 共通スタイル `/assets/blog.css`（一覧=body.bs-list、記事=.post-layout/.side/.cat-nav。PC=右サイドバー、900px以下=縦積み）
- RSS: `/news/feed.xml`（手書きRSS2.0）。ブラウザで開くと `/news/feed.xsl` がデザイン付きで描画

## PCの3列（2026-10-26〜・ユーザーの依頼「記事を画面の真ん中に」）
- **1,200px以上**: 左の列（228px）・記事（最大740px＝1行の長さは今までどおり）・右の列（264px）。外枠は最大1,320px。ヘッダー・タブ・見出しの帯も同じ幅
- **900〜1,199px**: 記事＋右の列（今までどおり）／**899px以下**: 1列（スマホは変えていない）。左の列は出さない
- 左の列は blog-site.js が全ページに自動で入れる（HTMLに書かない）: 記事＝この記事の目次（h2から作る・読んでいる所に色）＋あわせて読みたい（同じカテゴリ・同じタグを先に3本・絵つき）＋広告枠 `side_left`／一覧＝人気の記事（recommended）＋広告枠。左右の列はスクロールについてくる（sticky）
- **body の overflow-x は clip**（hidden だと sticky が効かない）。広告枠 `side_left` は ads.js の AD_SLOTS に空で用意（AdSense 承認後に縦長のユニットを作って入れる）

## モバイル表示ルール（右切れ対策）
- `.post-layout > * { min-width: 0 }` 必須（グリッドが幅広コンテンツで広がるのを防ぐ）
- **記事内の表は表のまま見せる。詰めて小さめ**（2026-10-27 ユーザーの依頼「隙間を詰めて文字を小さく。表で見せたいものは表で」）:
  文字はパソコン13.5px・スマホ12.5px、見出し12.5/11.5px、余白は上下5px左右7px（スマホ4px 5px）・行間1.5（assets/blog.css。記事ごとの <style> の 14px・8px 10px・行間2 より強い指定で上書き）
- **形は blog-site.js の `fitTables` が画面の幅に合わせて決める**:
  ①列ごとに一番長い文字数（補足の `.tp`・ふりがなは数えない）を数え、7字以内の列は折り返さない（`tb-nw`）・16字以上の列は左寄せ（`tb-tl`）、8字以内のセルは入りきるなら折り返さない（`tb-nw2`）、**5字以内のセル（名前・「基本無料」など）はどの段階でも折り返さない（`tb-nw5`）**
  ②入りきらない・セルが縦に長い（スマホ5行半・パソコン8行）なら、8字以内のセルも折り返す（`tb-loose`）→小さく（`tb-compact` 11.5px）→もっと小さく（`tb-tight` 10.5px・短い列も折り返す）
  ③それでも入らなければ左の列を固定して横にずらす（`tb-sticky`。幅は列ごとの「中身を1行にした幅（16字まで）」の合計）。**「1行＝1枚」のカードの形はやめた**
  セルの間には縦の仕切り線。記事ごとに付けた最低幅（`.wide` の760px・`.dt-tbl` の700px）と「見出し・1列目は折り返さない」は打ち消している。**新しい表に最低幅や nowrap を書かない**（形は fitTables に任せる）
- **表のセルは簡潔に。補足の「（…）」は次の行に小さく**: `python tools/table_breaks.py` が、セルの最後の「（…）」を `<span class="tp">`（次の行に小さく・灰色）に、
  文が2つ以上ある長いセル（30字以上）は「。」のあとで改行、「／」で3つ以上並べた長いセル（28字以上）は1つずつ改行にする（何度実行しても同じ）。**記事を足したら実行する**。
  全行同じ値の列は列ごと消して本文で一度だけ言う（例: アプリの料金「基本無料」）。URLは表に書かず「YouTube」などの短いリンクの文字にする。見出しは短く（「一般の人が使えるか」→「使えるか」）
- body { overflow-x: hidden } の保険つき

## サイドバー（右の列・スマホは記事の下）
- 「今月のおすすめ記事」（BLOG_POSTS の recommended・4本）・「最新のアップデート」（お知らせの新しい3本）・「公式SNS」。blog-site.js の `sideItem` / `sbHead`（2026-10-27〜）

## 記事の品質基準（2026-08-25の2度目の指摘後の水準）
- **その記事ならではの特筆点は、遊び心のある図・絵・構成で見せる**（2026-10-27 ユーザーの依頼）。文字と表だけで済ませない。例: 世界の麻雀＝国旗（tools/flags.py。香港・台湾は国旗でなく地域のピン）の「世界一周」ルート・牌の数くらべの帯・手牌13枚と16枚の長さくらべ／Mリーグの持ち越し＝消えた半分を点線で残す棒と「÷2」の階段／三麻＝抜く萬子に✕・北抜きの流れ・花牌と白ポッチと焼き鳥カードの絵。サムネイルも同じ特筆点を絵にする
- **本文4,000字級**（表・実例・FAQ・実体験を含める。薄い記事は追加しない）。
  2,500字級では2度目の「有用性の低いコンテンツ」を避けられなかった
- **テーマは「セット麻雀の運営・集計」に寄せる**。麻雀ルールの一般解説（役・リーチ・ドラ・符と翻）は
  他サイトと同内容になり独自性にならないため、新規記事は原則このカテゴリで作らない。
  既存のルール解説記事を触るときは、必ず「集計・運営の側から見るとどうか」の節を足す形にする
- **数字を書くときは必ず検算する**。スコア計算の例はindex.htmlの calcScores / rankGroups / applyChombo を
  別実装で再現して突き合わせる。符・翻の点数は 基本点=符×2の(翻+2)乗 から計算する
- **素点は「（終了時の持ち点 − 開始時の持ち点）÷ 1,000」で書く**（アプリの成績の素点と同じ・2026-10-02に全記事をそろえた）。返し点は「オカの大きさを決める点数」、オカは「全員が（返し点−持ち点）ずつ出し、1位がまとめて受け取る」＝25,000/30,000の四麻なら**1位 +15.0／2位以下 −5.0**。素点・ウマ・オカはそれぞれ合計0。「素点＝持ち点−返し点」「オカ＝+20を1位だけ」の書き方に戻さない（スコアの合計は同じだが、素点・オカの列の数字が変わる）
- **根拠のない確率・統計値は書かない**（「〇%」「〇回に1回」）。日付入りの作り話エピソードも禁止
- **記事に書く既定値はアプリのデフォルトとそろえる**。
  三麻は**35,000点持ち／35,000点返し（オカなし）／ウマ10-0-10**、四麻は**25,000／30,000／ウマ10-30**
  （index.htmlの`applyMode(n)`とクイックスタートの値）。
  2026-08-26まで記事側だけ35,000／40,000、2026-09-17まで30,000／35,000と書いており、
  読んでからアプリを開くと数字が違う状態だった。
  アプリ側の初期値を変えたら、この数字を使っている記事（sanma-yonma / house-rules / score-examples /
  score-mismatch / uma-oka / riichi / score-basics / faq）も一緒に直す
- **三麻35,000点持ちは3人で105,000点**＝一般的な100,000点の点棒セットだと5,000点足りない。
  点棒の話を書くときはこの数字で書く（「30,000点持ちなら90,000点で足りる」は旧既定の話なので使わない）
- 著者ブロックはblog-site.jsがCTA直前に自動挿入（個別HTMLへの記載不要）
- Article JSON-LDのauthorは `{"@type": "Person", "name": "むにぃ", "url": "https://majasco.jp/about.html"}` で統一
- 内部リンクを2本以上（関連記事へ相互に張る）

## タイトルの付け方（2026-10-30〜・ユーザーの依頼「YouTubeの動画タイトルのようにクリックしたくなる・記事ごとに区別できる」）
- **頭に【】の札を1〜2つ**（2026-10-30 ユーザーの依頼）。札のすぐ後に検索語（例：【完全保存版】麻雀の点数早見表｜…）。札の例: 対象＝【初心者向け】【初心者必見】【初心者がまず覚える】【プロ・上級者必見】【プロ試験】【幹事必見】【集計係必見】／中身＝【図解】【早見表】【比較表】【年表】【練習問題14問】【判定チャート】／量・手軽さ＝【5分でわかる】【10分でわかる】【保存版】【完全版】【完全保存版】／分野・時期＝【Mリーグ】【2026年】【上達】【マニアック】。年は中身が年ごとに変わる記事（おすすめ・プロテスト・タイトル保持者など）だけ。**点数早見表は【完全保存版】**（ユーザーの指定）
- 札のあとは、数字・固有名で区別する言葉
- 損を避けたい・知りたい気持ちに触れる言い方を一部に（【知らないとチョンボ】「実は麻雀用語だった！」「〜していい？だめ？」）。ただし中身と合わないあおりはしない
- 35〜45字ほど（60字まで）。用語ルールの禁止語は入れない
- 書きかえは `tools/retitle.py`（<title>・h1・og:title・twitter:title・Article の headline・BLOG_POSTS をそろえる）→ `python tools/blog_cats.py` → `node tools/build_post_lists.js`（**この順番**。逆にするとテーマの一覧ページに全テーマの記事が並ぶ）。新しい記事もこの決まりで付ける

## 表記の決まり（2026-10-30〜・ユーザーの依頼「ルビか（）か、複数の呼び方の表記を全ページで統一」）
1. 中国語から来た麻雀用語（役・牌・席・動作）は**漢字で書き、最初の1回に主な読みのルビ**（`tools/add_ruby.py` が READ の読みで自動で付ける）。見出しの役名も漢字＋ルビ（例：断么九＋タンヤオ）
2. **読みを（）や・＝で重ねて書かない**（×「刻子（コーツ）」「槓子・カンツ」「タンヤオ（断么九）」）。`python tools/notation_check.py` で数え、`--fix` で直す（読み方そのものを見せる用語集・正式名称・漢字の意味のページは対象外）
3. 読みが2つ以上あるものは、**主な読みをルビ、別の読みを名前の後ろに（）**（例：十三不塔＋シーサンプーター（シーサンプトウ）。CSSは `.yomi`）
4. カタカナで書くのがふつうの動作・状態の言葉は**カタカナ**: リーチ・ツモ・ロン・ポン・チー・カン・ドラ・テンパイ・ノーテン・フリテン・チョンボ。正式名と通称が違う役は、見出しは正式名（漢字＋ルビ）に「通称：ツモ」のように添え、本文では通称のカタカナを使ってよい
5. 牌の絵は**まじゃすこの牌（assets/tiles）だけ**。手牌の例は `hai_sheets.check()` であがりの形か確かめてから載せる。手描きの牌（記事の中の <svg> の四角）は使わない

- 麻雀の記事は **6つのテーマ**: はじめての麻雀（`beginner`・/beginner/）／ルールの深掘り（`rules`・/rules/。練習問題もここ）／スコア・集計（`score`・/score/）／Mリーグ・プロ（`pro`・/pro/。放送対局）／AI・ゲーム（`ai`・/ai/）／作品・カルチャー（`culture`・/culture/）。ほかに お知らせ（news）・雑記（blog）。

- `python tools/blog_cats.py` が、テーマの一覧ページ（/mahjong/ をひな形に）・記事のパンくず（トップ ＞ ブログ ＞ テーマ ＞ 記事）・sitemap・ブログのトップの「テーマから探す」（`.theme-grid`。テーマごとの本数と、いちばん新しい記事の絵）を作る。テーマの説明文はこのスクリプトの THEMES。色は assets/blog.css（`.cat-キー`・`.hero-キー`）
- **増えそうなテーマの候補**: 「上達・戦術」（何切る・押し引き・牌効率。待ち当て道場・論述問題もここへ移す）は記事が3本ほどになったら足す。AI・ゲームは記事が少ないが、これから増える見込みで独立させた
- 一覧ページのカテゴリのタブ（`.cat-nav`・sticky）は、上に残るヘッダーのすぐ下に止まる（blog-site.js が `--hh` にヘッダーの高さを入れる）

## 執筆の用語注意
- **「いま」と書かない（2026-10-26 ユーザーの好み）**。「現在の代表」「現在は」のように「現在」、会話や気持ちの言葉は「今、誰がトップ？」のように漢字の「今」。引用（Xのポストの文）はそのまま
- **表のセルの寄せ（2026-10-30〜）**: 文字の列は左寄せ、数字・点数・記号（○✕—）だけの列は中央寄せ。表を足したら `python tools/table_align.py`（数字の列の td と先頭行の th に `.c-n` を付ける）。見出しのセルの太さは800。点数表・符・答え・回し方・指名・漢字の表は、それぞれのCSSの寄せのまま
- **図・表・イラストを足したら必ず `python tools/overlap_check.py`**（2026-10-30〜・ユーザーの指摘「はみ出し・被りのミスが多い」）。幅360/390/768/1100pxで、牌の絵のセルや入れ物からのはみ出し・牌どうしの重なり・セルの数字のはみ出しを調べる。SVG の中の数字は `python tools/svg_text_check.py`（四角・丸に3px以上の余白）
- **表と図のそろえ方（2026-10-26〜）**: 先頭行のある表は thead に入れる（tbody の1行目に th を並べない）。先頭行の無い表（左の列が項目名）は tbody の th で書けば、上に青の線・左の列は薄い青の地になる（assets/blog.css「表と図のそろえ方」）。
  **順番・流れ・分類は図にする**：手順＝`<ol class="steps">`、段階・足し算＝`.hflow`（`.hf-step`／最後は `.goal`、足し算は `.hflow.plus`）、年表＝`<ol class="vtl" style="--c:色">`（`<span class="yr">`）、移り変わり＝`ol.dl-reps`（矢印でつながる）、分類＝`<ul class="tree">`（`.tn` の箱・`.key`＝強調・`.tt` に牌）。新しい記事で順番や分類が出てきたら、箇条書きや表のままにせずこれを使う。数の移り変わり＝`.bars`（横の棒グラフ・最後の棒はオレンジ）、だれが抜けるか等の割り当て＝`table.rot`、指名の順＝`table.snake`、押してその節へ移る流れ＝`a.hf-step`

## 記事の直し方は Search Console のクエリで決める（2026-09-18〜）
- **新規記事を足す前に、Search Consoleの「検索パフォーマンス → クエリ」を表示回数の降順で見る**。
  表示されているのにクリックが0の語＝「Googleは関連だと判断しているが、記事が答えになっていない」もの。
  ここを埋めるのがいちばん安い
- 2026-09-18に実測して分かったこと（過去3か月・表示5,773／クリック131／平均掲載順位10.1）:
  - **一般的な麻雀ルール解説（ドラ・鳴き・役一覧・符と翻など11本）は表示の63%を占めるがクリックは18回**（CTR 0.49%）。
    2〜4ページ目にいるということで、増強しても大手に追いつけない。**ここに時間を使わない**
  - **セット麻雀の運営・集計の記事はCTR 1.7%**（mawashi-uchi 3.0% / house-rules 4.0% / team-tournament 4.7%）。
    表示は少ないが効率が3.5倍。**伸ばすならこちら**
  - noindexで一般記事を落とす案は**却下**（月6クリックを失ううえ、表示回数の63%＝サイトの面積を失う）
- **「〇〇とは」のクエリで表示されているのに、記事にその語の定義セクションが無い**ことがよくある。
  2026-09-18に mawashi-uchi へ「抜け番とは」、uma-oka へ用語まとめ表を追加したのはこのパターン
- **サイト内に一度も書いていない語で表示回数が立っていたら、それは空き地**。
  例: 「名古屋 麻雀 3人打ち 違い」67表示に対し「名古屋」の記述が0字だった → sanma-yonma に地域差の節を追加
- 地域ルール・ローカルルールを書くときは**断定しない**（「〜として紹介されている形」「店や卓によって変わる」）。
  そのうえで**集計側から見た整理**に落とすと、他サイトの焼き直しにならない
  （例: 二翻縛りも抜きドラも半荘のスコア集計には影響しない。効くのは持ち点・返し点・ウマ・同点・トビの5つだけ）
