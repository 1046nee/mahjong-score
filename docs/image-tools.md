## スマホの枠（2026-10-27〜・すべての絵・画像・動画で必ずこの決まり）
ユーザーの指示「縦横比・上のデザインの配置・枠のデザインを必ず統一する（縦長すぎ・横長すぎは違和感のもと）」。幅 w に対して:
- **高さ＝w×2.06**（iPhoneの縦横比。これ以外にしない）
- 枠の太さ＝w×3.5%（上下左右同じ）／外の角＝w×15%／画面の角＝w×11.5%／枠の色 #1F2A28
- 画面のいちばん上に**帯（高さ w×10%）**を置き、その真ん中に**ノッチ（幅 w×30%・高さ w×7%・丸）**。帯の色は中のアプリの上の色（スクショの上端の色）。絵では帯は画面と同じ色でよい
- 本物の画面（スクショ）は帯の下に**幅いっぱい**で置く。下のはみ出た分は隠れる（枠の形を画面に合わせて変えない）
- 作る場所: SNS画像・動画は `tools/make_sns_v3.py` の `phone_frame()`（定数 PH_*。make_short.py も同じ関数を使う）／サイトは index.html の `.lp-phone` `.howto-phone`（`--pw` から計算）／サムネは `tools/make_thumbs.py` の `phone()`（高さを渡すと幅を決まりに合わせる）／SVGの絵（最初の画面・最後の画面・番外編・ブックマークの案内）は数字で決まりどおりに描いてある
- 新しくスマホを描くときも、まずこの決まりの数字を計算してから描く。小さなアイコンも高さ≒幅×2

## スクリプト（tools/。出力先はすべて「まじゃすこ素材/」）
- **`tools/make_sns_v3.py`（2026-10-27〜の標準）** — PILではなく、HTMLをブラウザ（Playwright）で描いて撮る。LPと同じ世界観（淡い緑の地・本物の画面のスマホ・飛び出す数字のカード・✨）。
  機能を1つずつ紹介するシリーズ feat-01〜10（IGフィード 1080×1350 と ストーリーズ 1080×1920 を両方）、使い方カルーセル howto-0〜4、intro、ogp4、x-header-v3。出力 まじゃすこ素材/v3/。
  画面は assets/screens/ の本物の画面（スクショ）。スマホはいつも画像の縦横比のまま**下の縁まで全部入れる**（切らない）。カードの数字は画面に写っている値と合わせる。
  はみ出し（カード・見出し・スマホがキャンバスの外）を撮るときに自動で調べて表示する。機能を足すときは FEATS に1行足す

## サイト画像のルール
- favicon: `/favicon.ico`（16/32/48。favicon.pngからPIL生成）＋ `/assets/favicon.png`（512）
- OGP: 現行 `/assets/ogp4.png`（2026-10-27差し替え。tools/make_sns_v3.py で作る。LPの最初の画面のイラストをそのまま使う）。旧 ogp3.png（2026-09-17）。
  **差し替えるときはファイル名を変えて全ページのog:image/twitter:imageを書き換える**（Xが画像URL単位でキャッシュするため同名上書きは反映されない）。旧ogp.png/ogp2.pngは残置
- ロゴ: `/assets/logo.png`（800×250透過・全ページヘッダー）

## 牌姿図（ブログ用インラインSVG）
- **tools/make_tile_svg.py** で生成（hand_svg=手牌1列／dora_map_svg=表示牌→ドラ対応図）。
  牌コード: m1..m9/p1..p9/s1..s9/E,S,W,N/Wh(白)/Gr(發)/Rd(中)。一索は鳥柄のため図では使わない（避けた手牌例を作る）
- 13〜14枚の手牌はmin-width:520px前後を持たせ、**必ず`<div style="overflow-x:auto">`で包む**（スマホは横スクロールで見せる）
- レイアウト確認はscratchpadのPILプレビュー（同じ座標表を描画）をReadで目視
- 掲載済み: リーチ記事=テンパイ例／役一覧=タンヤオ・役牌の完成形／ドラ記事=表示牌→ドラ対応図

## 実写真（ブログ用）
- **原本はまじゃすこ素材/写真/（private）**。公開するのはPIL加工後の `/assets/photo-*.jpg` のみ
- 加工手順: **人名・個人情報をPILの黒塗りで必ずマスク**（加工後にReadで目視確認）→ 幅1200pxへ縮小 → JPEG quality=82
- 記事への挿入は `<figure>`＋`loading="lazy"`＋altとfigcaption必須。キャプションに「（名前は伏せています）」を明記
- 公開済み: photo-score-notebook.jpg（集計係記事）／photo-score-sheets.jpg（集計係・ウマオカ記事）／
  photo-jantaku-hand.jpg（牌の種類記事）／photo-kotatsu-mahjong.jpg（持ち物リスト記事）
- 写真を差し込んだ記事はJSON-LDのdateModifiedを更新する

## セーフゾーン
- OGP（X表示）: 2:1で中央トリミング → 2100×1103は上下約26pxずつ切れる
- Xヘッダー: プロフィールアイコンが左下に重なる／端末により上下約60px切れる → 文字は中央帯に
- IG: **フィード画像は縦5:横4（1080×1350）で作る**（プロフィールグリッドが縦5:横4表示のため。1:1は使わない）。ストーリーズは1080×1920

## 落とし穴
- **スマホの枠に入れる画面は、画面いっぱいのスクショ（720×1558）を使う**。カードだけ撮った短い画像（my-h2h.jpg など）を入れると、スマホの下に空白ができる（2026-10-27 機能紹介4でユーザー指摘 → shoot_lp_screens の plan に自分の対戦成績 lp-myh2h を足して撮り直した）
- **スマホの枠はいつもiPhoneの縦横比（844:390）**。中身（要素のスクショ・短い画面）に合わせて枠を縮めると、横長のタブレットのような形になった（2026-10-13 ユーザー指摘）。短い中身は下をアプリの地の色で埋める（make_ig_v2.py の `iphone_screen`・make_ig_v2_oct.py の `phone`）
- **見本の試合の日付が古いと「記録の確定」で入力の画面が開かない**（shoot_app_screens.py は7月の日付。2026-10-13に撮り直したら確定の案内が写った）。撮影のときだけ lockAt を先の時刻にする。make_ig_v2.py の `crop_top`（ページ全体のスクショの切り出し位置）は画面の組み方が変わるとずれるので、撮り直したら全枚数を目視する
- リモート実行環境（Claude Code on the Web等）からは majasco.jp / Firebase への接続がegressポリシーでブロックされることがある
  → 実画面スクショは tools/shoot_app_screens.py のローカル起動＋Firebaseスタブ方式で撮る（本番データにも一切触れないので検証セッションの削除も不要）
- フォントパスはOS依存（Windows: C:\Windows\Fonts\NotoSansJP-VF.ttf ／ Linux: /usr/share/fonts/truetype/noto-jp/NotoSansJP.ttf に配置）。make_ig_v2.pyは両対応済み
- 可変フォントのweight指定を忘れると細字になる（try/exceptで握りつぶしているため気づきにくい）
- bashヒアドキュメント内のWindowsパス（\U等）はエスケープ事故のもと → スクリプトはファイルに書いて実行する
- 生成スクリプトはtools/に置く（scratchpadはセッションが変わると消える）
- **アプリのUIを変えたら画像スクリプトも探す**。2026-09-17に、カード名の変更（2026-08）と用語の中立化（2026-08-26）が
  tools/の画像スクリプトに反映されておらず、OGP・Xヘッダー・IG全シリーズが「スコア収支」のままだった。
  `grep -rn "<旧UI語>" tools/*.py` を変更のたびに回すこと
- **PILのテキストは枠内に収まるか毎回measureする**。`font.getlength(text)` で実測し、ボタン幅と比べてから座標を決める。
  2026-09-17にクイックスタート画像のボタン内テキストが右へはみ出した（見た目で調整せず数値で合わせる）
- **キャンバス比率の変更**はW,H定数の変更＋縦座標の再配分（glow中心・sparkle位置・phone_frameのy0・footer・closingのy）で対応する。
  過去に1080×1080→1440→1350と2回実施。変更後は**全枚数をReadで目視QA**（はみ出し・装飾かぶり・「ちょい見え」の見切れ装飾）
