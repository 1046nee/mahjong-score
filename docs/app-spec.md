# アプリ仕様（index.html）

※「今の正」だけを書く。経緯・改修履歴はgit log。仕様を変えたらこのdocも更新すること。

## データモデルと計算
- Firebase `sessions/{10文字ID}`（URL共有モデル）＋ localStorage `mahjong-v3`（履歴最大`MAX_HISTORY`**100件**・登録名）
- **履歴が消えにくくなる対策（第1段階・2026-08）**:
  ①`saveStorage`は容量あふれ（QuotaExceeded）で丸ごと失敗せず、**古い履歴から落として必ず保存を成功させる**
  （gamesは常に新しい順＝末尾が最古）
  ②履歴を持つ端末では`requestPersistentStorage()`＝`navigator.storage.persist()`で保存データの保護を要求
  （起動時とsaveToLocalHistory。Chrome系/Firefoxが利用実績から自動判断・ダイアログなし。Safariは非対応）
  ③過去の試合画面に**「ホーム画面に追加」の案内**（`showInstallHelp`モーダル。**iPhone→Android→PCの順で固定**。
  iPhoneはLP番外編と同テイストのSVGイラスト3枚で図解: ①アドレスバー右の「…」→②「共有」→③「ホーム画面に追加」→④「追加」。
  実機スクショ（まじゃすこ素材/iPhone画面/）を簡略化したもの。旧UI向けに「画面下の共有ボタンからでもOK」の注記つき）。
  iPhoneのSafariは**7日間使わないと保存データを自動削除する**が、ホーム画面から開く場合は対象外になる。
  **ただしiOSのホーム画面アプリ（standalone）はブラウザとは別の保存領域で動く**（localStorage非共有）＝
  追加しただけでは履歴は空。案内モーダルに正しい順番を明記する:
  ①引き継ぎURLを作る→②ホーム画面に追加→③アプリ側で引き継ぎURLを貼り付けて読み込む（1回だけ。以降はrefreshMyListで自動同期）。
  共有URLのリンクがホーム画面アプリで開かないのもOS仕様（リンクは常にブラウザで開く）で、これも同じ同期がカバーする。
  すでにstandalone起動中（`isStandaloneApp()`）なら案内`#hist-tip-install`を隠す。
  **過去の試合の注意書き・引き継ぎURLカードの文言は短く保つ**（2026-08-07に「丁寧だが長すぎて離脱する」と
  指摘され半分以下に圧縮。1行目=メリット、2行目=やること、の順。詳細な説明はお知らせ記事が担う）。
- **引き継ぎURL（第2段階・端末をまたぐ履歴。2026-08）**: 端末ごとに専用ID（**14文字**・セッションIDと同じ文字種）を発行し、
  `mylists/{ID}` に**参加したグループのID一覧だけ**を置く（`groups/{sessionId}: {at, name}`。本体はsessionsのまま二重に持たない）。
  `#my=ID` のURLを開くと別端末でも履歴一式が戻る＝会員登録なしの引き継ぎ。IDを知る人だけが読める（グループ共有URLと同じ思想）。
  - UI: 過去の試合画面のカード`#mylist-card`（`renderMyListCard`。未作成=「引き継ぎURLを作る」＋**貼り付けて読み込む入力欄**
    （`importMyListFromInput`。URL全体でも14文字IDだけでも可）／作成済み=URL表示＋コピー。
    **自分専用・人に送らない**の注意書き必須）。作成は`createMyList`（衝突チェック付き・現在の履歴を初期投入）。
    貼り付け入力は**ホーム画面に追加したアプリの唯一の取り込み導線**（standaloneはアドレスバーが無くURLを直接開けない）。
    **standaloneでは貼り付け欄を主役にした表示に切り替える**（見出し「ブラウザで使っていた履歴を引き継ぐ」・新規作成は控えめな副ボタン。
    アプリ側でここに来る目的の大半はブラウザの履歴を持ってくることだから）
  - **ホームの入り口は履歴0件のとき無条件に出す**（`renderRecentGames`の「履歴の引き継ぎ」セクション）。
    履歴0件で隠すと、保存領域が空から始まるホーム画面アプリでは引き継ぎ欄のある過去の試合画面へ一生たどり着けない。
    **`isStandaloneApp()`は端末によって外れる**（＝判定に頼ると「入り口が表示されない人」が出る。実際に報告あり）ため、
    **判定は文言の出し分けだけに使い、入り口そのものは判定に依存させない**:
    作成済み=「過去の試合・引き継ぎURL ›」／standalone=「ブラウザで使っていた履歴を引き継ぐ ›」／
    それ以外=「別の端末の履歴を引き継ぐ ›」。履歴が1件でも入れば「最近の試合」に置き換わって消える。
    タイトル`.rg-title`は状態で書き換えるので、履歴ありに戻ったら「最近の試合」へ復元すること
  - `isStandaloneApp()`は `navigator.standalone`（iOS）／`document.referrer`の`android-app://`／
    display-mode の standalone・minimal-ui・fullscreen・window-controls-overlay をすべて見る。
    それでも外れる前提で使うこと（上の無条件表示が最後の砦）
  - **`renderMyListCard`の主役の出し分けも判定ではなく履歴の件数で決める**（未作成のとき）:
    **履歴0件＝持ってくるものが無い＝引き継ぎたい**ので貼り付け欄を主役（見出しも「引き継ぐ」）、
    履歴1件以上なら従来どおり「引き継ぎURLを作る」を主役にする。
    判定で出し分けると、判定が外れたアプリで「案内は引き継ぐ・実UIの主役は作る」と食い違い、
    誤タップで空のリストを作ってしまう（入り口と着地の主役を必ず一致させること）
  - **作成済みカードにも乗り換え用の貼り付け欄**（details「別の引き継ぎURLを読み込む（乗り換え）」）。
    無いと、standaloneで誤って「新しく作る」を押した瞬間にブラウザ側URLへ乗り換える手段が消えて詰む
    （standaloneはアドレスバーが無く#my=URLを開けない。openMyListFromUrlは乗り換え対応済みなのでUIさえあれば戻れる）
  - **過去の試合の注意書き`#hist-tip-text`は状態で切り替える**: 未作成=「この端末だけに保存」／
    作成済み=「引き継ぎURLにも自動で追記」（作成済みなのに「この端末だけ」では直下のカードと矛盾する）
  - 同期: `saveToLocalHistory`→`syncGroupToMyList(g)`（1ページ表示につきグループごと1回だけ書く。`myListSynced`ガード。
    **別のリストに乗り換えたら`myListSynced.clear()`必須**＝忘れるとローカル側のグループが新リストに追記されない）。
    逆方向は`refreshMyList()`＝**起動時と過去の試合を開いたとき**にサーバーのリストから静かに取り込む
    （ブラウザ⇄ホーム画面アプリのように保存領域が分かれていても、双方が開くたびにそろう）
  - 復元・マージの本体は`mergeMyListData(data)`（openMyListFromUrlとrefreshMyListで共用）＝リストを取り込み→
    無いグループをsessionsから並列取得（新しい順・最大MAX_HISTORY件。**取り込んだゲームのプレイヤー名は
    「登録名」にも反映**＝この端末で作成した場合と同じ扱い。引き継ぎ後のセットアップで過去のメンバー名が候補に出る）→
    ローカルにだけあるグループはサーバー側へ追記（双方向）。openMyListFromUrlは**処理後にhashを消す**（再読み込みで二重取り込みしない）
  - **起動時のURL判定は #my= → セッションID（8文字以上）→ アンカー の順**。my=は8文字以上の条件も満たすため、
    先に判定しないとセッション参加に吸い込まれてエラーになる
  - **database.rules.jsonにmylistsノードを追加済み**（rules変更はコンソール手動貼り付けが必要 → docs/site-spec.md）
- **「この試合での自分」と「自分の成績」（2026-08〜）**: アプリは本人を特定できないため、**本人が卓ごとに自分の名前を選ぶ**設計。
  分類はlocalStorage `mahjong-tags-v1`＝`{gid:{role:'play'|'watch', me:index}}`（既定=自分未選択。既定は保存しない。保存キーは変えない）。
  - **画面に「参加／観戦」の区別は出さない**（2026-09-26。わかりにくいと指摘された）。`role:'watch'` は画面では**「自分は出ていない」**
    （記録係・見ていただけの試合＝成績に入れない）。見るだけの人は「見るだけのリンク」（下の節）で開くので、そもそも一覧に入らない
  - UI: 過去の試合の行の「自分の結果」（そのゲームでの順位・スコア）／未選択は点線の「自分を選ぶ」（`.gm-pick`）→`openTagEditor`
    （form-modal「この試合での自分」。名前チップ＋「自分は出ていない」。「まだ選ばない」は2026-09-29にやめた＝選び直すか出ていないにするだけ。何も選んでいなければ保存は押せない）
  - **引き継ぎURLにも同期**: `mylists/{id}/groups/{gid}` に `role`('play'|'watch')と`me`(0-39)。
    **rules.jsonに両キー追加済み（コンソール貼り付けが必要）**。ルール未適用でも本体同期が壊れないよう、
    at/nameを先にupdateし、role/meは別update・失敗は握りつぶす（分類は端末に残り次の機会に再送）。
    復元（`openMyListFromUrl`）はサーバー側タグを取り込み、サーバーに無い分は端末側から上げる
  - **自分の成績は2026-09-29に作り直した**（`renderMyStats`・下の古い説明より優先）: 期間 → **範囲**（個人（すべて）｜仲間ページごと。`msScope`）→［成績｜相手｜過去の試合］。**個人の範囲はマイページに載せた**（2026-09-29。`showView('mystats')` は `msScope === 'all'` ならマイページへ）。この画面は仲間ページの範囲（仲間ページのカード・メンバーの「自分の成績」から）だけ。
    成績＝マイページと同じカード＋5つのタイル（連対率・素点・順位点／最高・最低点数）＋推移、範囲が2つ以上なら**「くらべる」表**（ほかの表と同じ白いカード `.ms-card` に載せ、カードの幅いっぱい。色が違うのは見出しの行だけで、個人と仲間ページの列は地・文字の色・太さを変えない）
    （列＝個人・各仲間ページ、行＝試合数・平均着順・トップ率・連対率・ラス回避・通算スコア・素点・順位点。`msCompareHtml`）。
    仲間ページの範囲＝自分を選んだ試合のうち、その仲間ページに入っている試合だけ（`collectMyStats(inP, only)`・試合の一覧は `circleCardInfo[cid].sids`）。
    ゲームは打った日で「新しい順｜古い順」・月の見出し。仲間ページのメンバーの成績（自分）から「個人の成績とくらべる」で開ける
  - **自分の成績**（`view-mystats`。マイページ「個人」の「詳しい成績表 ›」「すべての相手 ›」から）:
    参加かつ自分設定済みのゲームを横断集計（`collectMyStats`）。同点は`rankGroups`按分＝個人成績と同じ数え方。
    **画面は［まとめ｜相手別｜ゲーム別］のタブ（`myStatsTab`）で、横スクロールの表は使わない**（2026-09-26。表が3つ縦に続いて読みにくかった）:
    - まとめ（`myStatsSumHtml`）: 四麻｜三麻の小さいセグメント（マイページの `mpMode` と共有）→ iOSの角丸リストで
      試合（ゲーム数・試合数・平均着順）／着順（`rankBarHtml`）／率（トップ率・連対率・ラス回避＋「1着 10/32」）／スコア（通算・素点・順位点・最高・最低点数）
    - 相手別（`myH2HCardHtml`）: すべて｜四麻｜三麻（`myH2HMode`）→ 相性のカード2枚（`h2hPairCardsHtml`）→ 相手ごとの行（`h2hListHtml`。
      勝率・勝ち負けの棒・試合数・差。押すと開いて同じ試合・平均着順（自分／相手）・スコア差）
    - ゲーム（`msGamesHtml`）: **マイページの過去の試合と同じ1行**（`historyItemHtml`：順位・スコア・相手）。上の「四麻｜三麻」で絞る。「一覧｜タイル｜カレンダー」（マイページと共用の `histView`・カレンダーは `calS.ms`）。押すと結果詳細
    スコアは各ゲームのルールで計算された値の合算である旨を注記する。
    **画像は今までどおり表**（`myStatsTableHtml`＝四麻/三麻の2列・`h2hRowsTableHtml(…, true)`・`myStatsGroupsTableHtml(st, true)`）。
    **表の長文対策**（画像の表）: 項目列は**78px**（「通算スコア」=5文字が収まる幅。64pxでははみ出す。行名は「ゲーム数」）。
    ゲーム名は`.ms-gname`（内側span）で**3行打ち切り＋折り返し**・全文はtitle属性
    （`.rounds-table td.sticky-col`の`white-space:nowrap`を打ち消す。clampはtdでなく必ず内側のspanに掛ける）。
    「チーム戦」は形式列の9pxサブ行（`<div>`2つ構成＝画像側でメイン＋subsとして描かれる）。
    画像出力=`buildMyStatsCanvas`（帯「自分の成績」＋成績まとめ・対戦相手別・ゲーム別の表）。表HTML→Canvasの共通部は`imgTableHtmlCanvas`
    （imgTableBodyCanvasから抽出。**新しい表を画像化するときはこれを使う**）。
    グループ名なしの画像は`openImagePreview`/`shareCanvasImage`がタイトル・ファイル名を「ラベルのみ」にする
- **セッションIDは`newSessionId()`で発行**（生成→既存チェック→被っていたら作り直し、最大5回。誕生日問題による他人のセッション上書きを防ぐ）。
  初期のIDは22桁だったため、既存データには22桁IDも混在する（セキュリティルールは両方許可）
- **起動時のセッション判定は「ハッシュ8文字以上」**（ページ内アンカー #howto をセッションIDと誤認しないため）
- `settings`: playerNames（3〜40人=MAX_MEMBERS）/ numPlayers（3|4）/ startPoints / returnPoints / uma[] /
  rate・chipRate（**旧キー。画面では使わない**。新規は 0 / 1）/ bonusEnabled（チップ記録）/ startChips（持ちチップ）/ yakitori /
  chombo / chomboPenalty（罰符pts・0=マークのみ）/ teamMode / teams=[{name, members:[playerNamesのindex]}]
- `rounds[]`: points[] / scores[]（チョンボ罰符適用後）/ members[]（参加者index）/ chips[]（**チップ差**）/ yakitori[] / chombo[] / at / edited
  ／ id（その試合を追加した操作のID。2026-09以降の試合のみ）／ op（最後に修正した操作のID）
- `log[]`: type（add / edit / delete / **settings**）／ at ／ no（試合番号）／ points・prev・names ／
  op（その操作のID＝二重適用の判定に使う）／ settingsは label ＋ changes[]（「ウマ: 10-30 → 10-20」のような変更点の行）。
  旧形式の設定変更・「元に戻す」は type:'edit' で no が無い（`logKind(e)` が 'settings' に分類する）
- チョンボ: `applyChombo(scores, chomboArr, s)` が罰符ptsを減算。**submitRoundとsaveGameEditの両方で必ず通す**。焼き鳥はマークのみ
- **名称の表記は「ゲーム名」に統一**（2026-08-08。旧「グループ名」。セットアップのラベル・検索placeholder・
  CSVメタ行・成績シートの行名「ゲーム数」・LP・privacy/terms・news記事まで一括変更。
  変数名`MAX_GROUP_LEN`や保存キーは互換のため据え置き。「グループ」という概念語（グループを作成・共有URL等）はそのまま）
- **名前の文字数上限**: プレイヤー名=`MAX_NAME_LEN`**16**／チーム名=`MAX_TEAM_LEN`**40**／ゲーム名=`MAX_GROUP_LEN`**40**。
  プレイヤー名だけ短いのは表の列見出し（1列58px）になるため。チーム名はcolspanでまとまる／順位カードは1行使えるので長くできる。
  **40文字のチーム名は折り返し前提**で、伸びすぎないよう3行で打ち切る場所がある（表見出し`.team-head-name`・順位カード`.score-name`。
  どちらも`-webkit-line-clamp:3`。thをflex/boxにすると表のセルでなくなるので必ず内側のspanに掛ける）。
  全文はtitle属性・設定カード・結果画像で読める（**画像出力はtextContentを読むので打ち切りの影響を受けない**）。
  入力欄の`maxlength`＋保存時の`clampName`（**書記素クラスタ単位**で切るので絵文字が割れない）の二段構え。
  かける場所はセットアップ／設定変更モーダル／チーム編成エディタ／過去の試合の編集の全入力。
  **既存データに上限超えの名前があっても切り詰めない**（表示は従来どおり＝互換性を壊さない）。
  サーバー側の上限はdatabase.rules.jsonのname≤120・playerNames各≤60（こちらは変更していない）
- **規模の上限**（増えすぎると成り立たなくなるものに置いた線）:
  メンバー`MAX_MEMBERS`40人／1グループの試合数`MAX_ROUNDS`**500**／履歴ログ`MAX_LOG`**600件**（古いものから捨てる`appendLog`）。
  試合数の根拠は①保存のたびに全試合ぶんを書き直すので通信が重くなる（4人500試合で約85KB・1000試合で約168KB）
  ②試合結果の画像が読める大きさの1枚に収まらなくなる ③rules.jsonのrounds indexが4桁まで。
  上限に達したら**新規入力だけ**を止める（既存試合の修正・削除は常に可能）。残り20試合で予告のトーストを出す。
  チーム数に別途の上限は置かない（1チーム1人が下限なのでメンバー数＝40が実質の上限。TEAM_COLORSも40色）
- **互換性ルール（最重要）**: 旧データはキー無し=無効・0枚・1倍扱い。members無しの旧ラウンドは先頭numPlayers人参加とみなす（`roundMembers(r,s)`に集約）。保存キー名・関数名はbonus系のまま変えない（settings.rateも不変）

## 主要関数マップ
- **画面遷移と戻るボタン**: 左上の`#header-back`（36px円形・ゲーム設定と同仕様）を全画面に展開。
  戻り先は`backTargetOf(name)`のマップ＝setup/history→home ／ mystats→history ／
  detail→開いた場所（`detailBackTo`: history or mystats。viewDetailで記録、詳細内の再描画では上書きしない）／
  game→goHome（保存とリスナー停止を通す）／ home・share（作成完了の順方向フロー）には出さない。
  **ホーム画面に追加したアプリ（standalone）はブラウザの戻るボタンが無い**ため、画面内に必ず戻り道を置くのが原則。
  popstate（Androidの戻るボタン・ブラウザの戻る）では ①開いているモーダル・シートを全部閉じる
  （下だけ画面が変わる事故防止）②対局画面から離れるならleaveGame相当の後始末（履歴への保存・リスナー停止）を通す
- 同点処理は `rankGroups(values)` に一元化（ウマ・オカ按分・平均順位すべてこれ）
- 集計: `gameTotals` / `playedFlags` / `chipTotals`。チップ基準値は `chipBaseline(m)` = 持ちチップ + 過去試合のチップ差累計（修正時は対象試合より前まで）
- 結果カード: `scoreMainHtml(g)`（ゲーム=#score-main-body、詳細=`renderDetailBody(g)`。`viewDetail`=そのラッパ。チップ差・焼き鳥・チョンボの回数は個人成績の行）
- チーム: `normalizedTeams` / `teamStandingsHtml` / `memberDisplayOrder`（チームA→B…の表示順）/ `teamColorOf` / `teamDotHtml`。
  編成エディタは `teamEditorCtx` でセットアップ・設定変更モーダル共用。`syncTeamsWithIds`が同期を一元処理
- **チーム戦の制約**: 同チーム同士は対局不可。最低チーム数=1試合の人数（四麻4・三麻3、`teamEditorCtx.minTeams`）。
  ガード: toggleSheetMember / submitRound / defaultParticipants

## 送信キュー（入力を失わない・他の人の入力を上書きしない。2026-09〜）
- **背景**: 「入力完了で自分の画面には出たのに他の人には届かず、再読み込みしたら消えた」事故。原因は
  ①保存のたびに手元の rounds 配列を丸ごと書いていた（圏外で古い画面の端末が復帰すると、他の人の試合を上書きして消す）
  ②Firebaseの送信待ちはメモリにしか無い（送る前に再読み込み・アプリを閉じると入力ごと消える）の2つ
- **仕組み**: 1回の操作を op（kind: add / edit / delete / settings / rename / restore）として
  ①端末の送信キュー（localStorage `mahjong-outbox-v1`）に積む →
  ②画面は `overlayPending(serverGame, sid)`＝サーバーの値に未送信opを重ねて表示（`activeGame`はこれ。サーバーの生の値は`serverGame`）→
  ③`flushOutbox` が積まれた順に `sendOp` で `sessions/{id}` 全体をトランザクション（applyLocally=false）→
  ④確定したらキューから消す
- **中身は純粋関数 `applyOp(game, op)`**（トランザクション・重ね表示・tests.htmlで共用）。戻り値は
  apply／already（適用済み＝再送・二重送信）／conflict（他の人の変更とぶつかった）。
  **二重登録しない**: logに op のIDが残っていれば already（追加は試合のidでも判定）
- **ぶつかったときは上書きしない**: 修正・削除は「そのとき見えていた中身の指紋」（`roundTarget`＝id or at ＋ `fpOf(roundCore(r))`）を持ち、
  他の人が先に変えていたら反映せず知らせる（入力した点数をトーストに添える）。
  設定・名前の変更は「編集を開いた時点の値」（`editBase`）の指紋を持ち、変わっていたら反映しない。
  設定の編集中に他の人が先に変えたときは、保存ボタンの時点で気づいて開き直す（サーバー側でも applyOp が二重に確かめる）
- **スコアは適用するときにサーバーのその時の設定で計算する**（op には点数・参加者だけを持たせる）。
  入力中にメンバーが並び替え・追加された場合は `remapMembers` が名前で付け直す（名前の変更は人数が同じなら番号のまま）
- **送る契機**: `.info/connected` がtrueになったとき・`online`・画面に戻ったとき（visibilitychange）・未送信があるあいだ15秒ごと・起動時。
  つながっているのに45秒返ってこないトランザクションは打ち切って送り直す（同じopは二重に適用されない）
- **見せ方**: 画面上部の帯 `#sync-bar`（ヘッダー直下・sticky）。
  オフラインで未送信あり＝「未送信 N件：電波が戻ると自動で送信します（画面を閉じても消えません）」／
  オンラインで2.5秒以上送れない＝「送信中… N件」／権限・検証エラー＝「送信できなかった入力」＋もう一度送る・破棄／
  未送信なしでオフラインが4秒以上続く（ゲーム画面のみ）＝「オフラインです。他の人の入力は、電波が戻ると表示されます」。
  送れていない試合の行には「未送信」印（`.pend-mark`。1.2秒たってから見えるCSSアニメーション＝普段はちらつかない）。
  帯を出したあと全部送れたら「未送信だった入力を送信しました」
- **権限・検証エラーは捨てない**（`failed` を付けてキューに残し、帯で知らせる）。何度送っても通らない種類なので自動再送はしない
- **【最重要】`sessions/{id}` の直下に新しいキーを足さない**。トランザクションはゲーム全体を書くので、
  database.rules.json の `$other: false` に引っかかると**本番の保存が全部失敗する**。スタブ（smoke_test等）にはルールが無いので気づけない。
  保存まわりを触ったら **`python tools/sync_test.py`（本番DBで2台の端末を再現・検証用ゲームは自動削除）** を必ず通す
- 設定変更の変更点は `describeSettingsChanges(base, next, editMembersState)` が作る
  （ゲーム名／メンバー追加・名前変更・削除・並び順／持ち点／返し点／ウマ／チップ記録・持ちチップ／焼き鳥／チョンボ・罰符／チーム戦・編成）。
  何も変わっていなければ保存しない（「変更はありませんでした」）

## ログイン（Google・任意）とアカウント同期（2026-09-25〜）
- **目的**: iPhoneのブラウザ・ホーム画面アプリ・LINEの中のブラウザは保存領域が別々で、引き継ぎURLを手で移す作業が要っていた。

  （`#form-modal:has(.sheet-body)`。`:has` の無い端末は今までの中央のダイアログ。設定の編集など他の form-modal には効かない）
- `showView`: **未ログインで history・mystats を開くとログイン画面（`view-login`）**、ログイン中にログイン画面を開くとマイページ。
  ヘッダーの`goMyPage()`・試合の画面の下の「マイページ（過去の試合・自分の成績） ›」も同じ振り分け。`#mypage`・`#login` で開いたときはログイン状態が分かってから振り分ける（`pendingMyPage`）
- ログイン画面から押したログインは、戻ったらマイページを開く（`mahjong-after-login`。リダイレクトは押したときのURL＝/ に戻るため）
- **ログインは端末に保つ**（`setPersistence(LOCAL)`＝ブラウザを閉じてもログアウトしない）。iPhoneのSafariは7日間開かないとサイトのデータを消すことがあり、そのときだけログインし直し（記録はアカウント側に残る）
- **ログアウトすると、この端末の控え（過去の試合・自分の選択・仲間ページの一覧）を消す**。記録はアカウントに残っている。残すと、同じ端末で次に別の人がログインしたときにその人のアカウントへ混ざるため
- 未ログインでも、この端末で開いた試合は裏で控えておく（`saveToLocalHistory`）。**画面には出さず、ログインしたときにアカウントへ引き継ぐため**。
  トップ（LP）の「最近の試合」は最後に開いた順に2件まで（未ログインでも。docs/lp-spec.md）
- 旧「引き継ぎURL」（`#my=`）は、ログインしてアカウントへ移す入り口としてだけ残す（`openMyListFromUrl`→`importPendingMyList`）
- 「あなたはどれ？」はログイン中だけ出す（その場限りで遊ぶ人には聞かない）。選択肢は名前・「自分は出ていない」・「あとで」

## 対局の終了と記録の確定（2026-09-29〜。ルールは docs/site-spec.md）
- **目的**: 過去の試合をいつまでも誰でも書き換えられると、誤操作や改ざんの余地になる。確定した試合は**サーバーのルールで**誰も書き換えられない（読むのはできる）
- **終了**: 試合の画面の下の「対局を終了する」（試合が1つ以上あるときだけ）→確認→`setGameEnded(true)`＝トランザクションで endedAt＝今・lockAt＝今＋12時間。
  終了後は「＋ 点数入力」を隠し、上に「対局は終了しました。M/D hh:mm に記録が確定…」＋「再開する」（`#game-state`・`gameStateHtml`）。
  **猶予（12時間）のうちは既存の試合の修正はできる**（締め切りは延びない）
- **再開**: `setGameEnded(false)`＝endedAt を消し lockAt＝今＋24時間（lockAt はルールで消せない）
- **終了を押していない試合も、最後の内容の変更から24時間で確定する**（2026-10-02 ユーザーの判断。以前は終了しない試合は確定しなかった）:
  作成時に lockAt＝今＋24時間（`createGame`）、点数の入力・修正・削除・設定・名前・並べ替え（送信キューの op）のたびに今＋24時間へ延ばす（`sendOp`。終了後は延ばさない）。
  試合の画面の「対局を終了する」の下に「終了しなくても、最後の入力から24時間で確定します（いまのままなら M/D hh:mm）」。
  **1つのゲームを日をあけて続ける使い方はできなくなった**（FAQも「日ごとに新しいゲーム＋仲間ページでまとめる」に直した）
- **lockAt の無い古い試合**（2026-10-02 より前に作った試合）: `lockAtOf(g)`＝「最後の編集（作成・各試合の入力日時・履歴の時刻のいちばん新しいもの＝`lastEditMs`）から24時間」で
  確定したものとして扱う（`isGameLocked` はこれを見る）。試合を開いたとき（リスナー）・マイページで読み直したとき（`refreshHistoryGames`）・仲間ページで読んだとき（`lockCircleGames`）に
  `stampLockAt` がトランザクションで lockAt を書き込む（過ぎていれば過去の時刻＝その場でサーバーでも確定。ルールは lockAt が無い試合にだけ過去の時刻を許す）
- **確定後**（`isGameLocked`＝`lockAtOf(g)` ≦ サーバーの今）: 試合の画面・結果詳細に「記録は確定しています」、点数入力・設定の編集・行のタップを出さない。
  入口の関数（openSheet・openRoundMenu・openGameEdit・editDetailRound・openDetailEdit）にも門番。送信キューは確定した試合に書かず `locked` で知らせて捨てる
- **時刻はサーバーの時刻**（`.info/serverTimeOffset`→`serverNow()`）。ルールの now と端末の時計がずれても、締め切りの範囲（11〜25時間後）から外れないように
- 見るだけのリンクの写しにも lockAt・endedAt を載せる（見るだけの画面にも状態が出る）
- 送信中の入力が残っているあいだは終了・再開を押させない（先に送り切る）。オフラインでも押させない

## 共有シートと見るだけのリンク（2026-09-26〜）
- **試合のURL（`#試合ID`）は、開いた人が点数を入力・修正できる**＝同じ卓の仲間に送るもの。**SNSに載せる・観戦の人や来られなかった人に送る**ときは、
  点数を変えられない**見るだけのリンク（`#v=見るだけID`・12文字）**を使う
- **共有シート**（`openShareSheet(id?)`。試合の画面・結果詳細のタイトル横「共有」、過去の試合の「…」→共有）:
  ①一番上＝「一緒に打つ人に送る」（入力できるURL・コピー・LINEで送る。緑の地・i-pencil・「入力できる」のピル）
  ②「見るだけのリンク」（まだ無ければ「作る」ボタン＝`makeViewLink`。青の地・i-eye・「見るだけ」のピル。クラスは `.sh-opt.ro`）
  ③結果を画像にする。**その場限りで使う人が迷わないよう、①をいちばん目立たせ、作成直後の画面（view-share）は今までどおり①だけ**。
  スマホではボトムシート（`#share-sheet.sheet-body`）
- **仕組み（試合IDを漏らさない）**: `sessionViews/{試合ID}` = 見るだけID（試合IDを知っている人だけが引ける）／
  `views/{見るだけID}` = { s: 試合の写し（誰でも読める。name・createdAt・settings・rounds＋指紋h・操作数lv・更新日時at。**試合IDとlogは載せない**）,
  p: 「試合ID_n」, n: 書くたびに変える12文字 }（p・n は読めない）。ルールが p から試合IDを取り出して試合があるか確かめ、n を毎回変えさせるので、
  **リンクしか知らない人は写しを書き換えられない**（database.rules.json。確認は tools/view_rules_test.py）
- **写しの更新**: 試合を開いている端末（リスナーが値を受け取るたび）と、点数を送った端末（送信キューで確定したop）が`noteGameChanged(sid)`→
  1.2〜2.7秒待って`syncViewNow`。写しの元は**サーバーの値**（`serverGame`か sessions を読み直す。未送信の入力は載せない）。
  **中身の指紋 h が同じなら書かない／サーバーの写しの lv の方が大きい（こちらが古い）なら書かない**＝全員が同時に書いても内容は1つに収束する
- ルールを貼る前（sessionViews が読めない）は `viewFeature=false` で、共有シートに見るだけのリンクの欄を出さない
- **見るだけの画面（`view-watch`）**: 結果詳細と同じ部品（`renderDetailBody`を`detailRO=true`で描く）で、試合行のタップ・「仲間ページに追加」・設定の編集を出さない。
  `#v=`で開いたら `views/{ID}/s` を聞き続けて自動で更新（「最終更新 hh:mm」）。**その端末の過去の試合には入れない・「あなたはどれ？」も出さない**。
  最後に「まじゃすこを使ってみる」の案内（LPへ）。見つからないリンクは「見つかりませんでした」
- 仲間ページを見ているだけの人（メンバーでない人）が試合を押すと「結果を見る」＝`openWatchGame(circleSess[sid], 'circle')`（入力の画面は出さない）。
  メンバーは今までどおり「試合を開く（入力・修正）」
- 起動時のURL判定: #v= は #c= の後・セッションIDの前（「v=」＋12文字は8文字以上の条件も満たすため）

## 仲間ページ（circles・2026-09-25〜）
- **目的**: その場限りの試合とは別に、身内・大人数・大会の試合を仲間ごとにまとめ、自分が入っていない試合も含めた通算順位・対戦成績を全員で見る。
  1人が複数の仲間ページを持てる。1つの試合を複数の仲間ページに入れてもよい
- **立場**: 見る人（閲覧リンク `#c=ID`・ログイン不要・LINEの中でもOK）／編集メンバー（ログイン＋招待リンクか参加コードで参加）／
  管理者（作成者が任命）／作成者。**点数入力（sessions）は今までどおり誰でもログインなし**。ログインが要るのは仲間ページへの追加から先だけ
- データ（ルールは docs/site-spec.md）:
  - `circles/{cid}` = { id, name, createdAt, owner, roster: {mid: {name, at, uid?}}, games: {sid: {at, name, addedBy, addedByName, addedAt, seats: {席: {mid, by, byName, at, self}}}}, log }
  - `circleMembers/{cid}/{uid}` = { role: owner|admin|editor, name, joinedAt, code?, mid? }（メンバーだけが読める）
  - `circleSecrets/{cid}` = { code }（メンバーだけが読める）／`circleInvites/{code}` = cid（コードを知っていれば引ける）
  - `users/{uid}/circles/{cid}` = { at, name }（自分が参加している仲間ページ）。見ただけの仲間ページは localStorage `mahjong-circles-v1`
- **「本人」と「他人がまとめただけ」を区別する**:
  - 名簿の人に`uid`がある＝その人がログインして「これは私」と登録した（**本人の印**＝i-verified＋「本人」）。無い＝名前で結びつけただけ
  - 席の結びつけ`seats`は、結びつけた人（by・byName）と日時を必ず持つ。`self:true`＝本人が自分の席を結びつけた
  - **self の席は、本人・作成者・管理者だけが変えられる**。本人が登録した名簿の人の名前変更・名簿からの削除も同じ（`canChangeSeat`・`canEditRosterMember`。ルールでも同じ制限）
  - 本人登録すると、ほかの人がその人に結びつけていた席を「本人として確認」できる（`confirmMySeats`）
- **試合の追加**: 仲間ページの「試合を追加」（この端末の試合から選ぶ＋LINEのトーク履歴などを貼り付けて`extractSessionIds`で取り込む）、
  または試合の画面・結果詳細の「仲間ページに追加」（i-people）（名簿と名前がよく重なる仲間ページが上に並ぶ）。
  名前は`autoBindNames`（personKeyが同じ＝同じ人・仮名A・B…は結びつけない）。まとめて取り込むときは名簿にない名前を新しい人として足す。
  試合の画面から1試合だけ足したときは、未結びつけがあれば結びつけの画面をすぐ開く
- **見出し**: タイトルは全幅で2行まで（24px）、下に四麻・三麻ごとの数（次の行）＋立場のピル（`.ch-role`）、
  見出しの下に**四麻と三麻を分けて「対戦した人数・ゲーム数・計試合数」**（`circleCountsHtml`。名簿に結びついた席は名簿の人、ほかは名前で数える。無い形式は「まだありません」）。
  **共有・設定はその右に横に並べる**（`.ch-meta`・`.ch-act` 高さ30px・数の行は折り返さない。320px幅など入らないときは下の右へ回る。設定はメンバーだけ）。試合のタブの下の長い説明書きは出さない
- **画面はタブで切り替える**（2026-09-26。`circleTab`・`.seg.sm`）: **順位**（表彰台＋リスト。指標＝通算スコア/平均着順/トップ率/ラス回避/素点・順位点の横スクロールのピル `.pill-row`。
  **試合数に関係なく全員まとめて順位にする**（2026-09-29・ユーザーの判断。規定打席のような「参考」の分け方と、下の説明文はやめた）。
  表彰台は単色の台（金銀銅）＋メダル。4位以下の棒は、通算スコア・素点・順位点なら**0を中央に置いて左右に伸ばす**（プラス＝紺・マイナス＝赤。
  -6.0 と -285.0 が同じ向きに見えないように）、平均着順・率は左から伸ばす）／
  **成績表**（`circleGridHtml`。列＝メンバー（通算スコア順）・行＝試合数/ゲーム数/平均着順/1..n着/トップ率/連対率/ラス回避/通算スコア/素点・順位点/最高・最低点数。
  画面は明るい見出しの `.tbl-soft`（名前の上に頭文字の丸・1着〜n着の行に着順の色の見本 `.rk-mini`）、**画像も画面と同じ `.tbl-soft` の表**（`showCircleImage`＝成績表だけ。頭文字の丸と着順の見本だけ省く）。成績表のタブの下に**総当たり表**（「画像」つき＝`showCircleMatrixImage`・`mxTableHtml(…, forImage=true)`）。
  いちばん良い値は淡いゴールドの地＝ゲームの個人成績と同じ）／**対戦**（だれから見る？＝アバターの横スクロール（自分が先頭）→相性のカード→
  相手ごとの行 `h2hListHtml`（自分の成績の相手別と同じ部品）。総当たり表`circleMatrixHtml`は成績表のタブへ移した（セルは勝ち越し＝紺・負け越し＝赤のピル＋凡例。表の中でスクロールし上の名前の行を固定））／
  **試合**（カレンダー型の日付・試合数・1位の人・「未結びつけ n人」（琥珀色）／「結びつけ済み」のピル）／
  **メンバー**（名簿＋各人の順位（1〜3位はメダル）・成績の要約・変更の履歴）。
  四麻と三麻があるときは順位・成績表・対戦の上に小さいセグメント。画像: 順位タブの「画像」＝**画面の見たまま**（`circleRankCanvas`：表彰台＋4位からの行・選んでいる指標・期間。並びは画面と同じ `circleRankOrder`）。成績表タブの「まとめ画像」＝これまでの「通算順位の表」＋「成績表」（`showCircleImage`）
- **メンバーの成績**（`openCircleMember`。スマホではボトムシート）: 大きいアイコン・名前・本人の印（`circleBadge`＝i-verified＋「本人」）・
  「通算○位 / n人」（1〜3位はメダルの色）→ 成績（マイページの「個人」と同じ部品を淡い地の箱に）→ 相手ごとの成績（相性のカード＋`h2hListHtml`）→
  結びついている試合（開閉）→（メンバーなら）これは私／本人として確認 → **管理**（名簿での名前・同じ人としてまとめる・本人の登録を外す）。

  ②一緒に管理する人を招待（編集できる。メンバーにだけ出す・参加コードも）。`openCircleInvite` はこれを開くだけの別名
- **総当たり表（画面）はセルを「勝ち-負け」（例 57-74）にし、はみ出さないよう列の幅を自動で決める**（`mxTableHtml`。仲間ページとゲームの対戦成績で共用）:
  表の中でいちばん長い「勝ち-負け」の文字数から列の幅（文字数×7.4px＋余白・最低50px）を決め、全部の列を同じ幅にする。
  桁が増えたら表が横に広がり、横スクロールで見る（セルからはみ出さない）。名前は省略（全文は title）。マスを押すと「A → B：57勝74敗（131試合）」。
  2026-09-29に一度勝率の表示にしたが、ユーザーの希望で勝ち-負けに戻した（13人・4500試合・3桁の数で320px幅を確認済み）
  **常に表示する**（ゲームの対戦成績でも開閉の中に隠さない）。向きが一目でわかるように: 表の上に「**左の人**から見た、**上の人**との直接対決」、
  左上の角は斜線で「相手→／見る人↓」、列の見出しは「vs 名前」、「だれから見る？」で選んでいる人の行を塗る。左の名前を押すとその人から見る（`mxLegendHtml`・`mxTableHtml(…, onRow)`）
- **対戦成績の相手ごとの表示は2列のカード**（`h2hGridHtml`・仲間ページの対戦と自分の成績の相手で共用）: 名前・「13勝 6敗」を大きく・勝率の棒と％・試合数・スコア差・平均着順（自分 / 相手）。
  勝ち越しは青、負け越しは赤の枠。上に選んだ人の合計（`h2hTotalHtml`：n勝n敗・勝率・相手の人数）、並び順は「試合数順｜勝率順」（`h2hSort`）
- **「相性がいい相手／手ごわい相手」は出さない**（2026-09-29。ゲームの対戦成績・仲間ページ・自分の成績の相手別・メンバーの成績のすべて。相手の一覧・総当たり表と情報が重なるため）
- **メンバーの成績は必要な情報に絞る**: 成績はマイページのカードと同じ中身（`mpStatsInnerHtml`：平均着順・通算スコア・トップ率・ラス回避・着順の帯・最近）。
  目安の線・回数・推移のグラフ・相性のカード（相手の一覧と重なる）は出さない。相手ごとの成績は一覧（`h2hListHtml`）だけ
- **仲間ページで自分を選ぶと、個人の成績にも入る**（`syncCircleGamesToMine`・2026-09-29）: 名簿で本人登録した人に結びついている試合を、自分の過去の試合に入れ、その席を「自分」にする。
  動くのは: 本人として登録したとき（確認の返事を待たない）・本人として確認したとき・結びつけを保存したとき・仲間ページを開いたとき。
  自分で一覧から消した試合（削除印）は入れ直さない。すでに自分の選択（名前・出ていない）がある試合は変えない
- **同じ試合は1つの仲間ページに1回だけ**: `games/{試合ID}` がキーなので2件にはならず、ルールでも「無いときだけ作れる」（別の人が上書きできない）。
  `addGameToCircle` は試合の登録を先に書き、通ったときだけ名簿に新しい人を足す（ほぼ同時に2人が追加しても名簿の人が二重にできない）。
  すでにあれば `{ already, by }` を返し「○○さんがすでに追加しています」
- **この試合が入っている仲間ページを、試合の画面・結果詳細の上に出す**（`renderGameCircles`・`#game-circles`/`#detail-circles`）: 「金曜会 に追加済み（むにぃさん・9/29（火））」。
  調べるのは自分が参加している・見たことのある仲間ページ（`allCircleEntries`）だけ（1分は結果を使い回す）。追加の画面でも追加済みの仲間ページに誰が追加したかを出す
- **表記ゆれ**（「たろう」と「太郎」）は、名簿の人のページの「同じ人としてまとめる」で直す（席を付け替えて名簿から消す）。本人登録された人は消える側にできない
- **変更の履歴**（`circles/{cid}/log`・追記のみ）: 誰が・いつ・何をしたか。結びつけ・試合の追加・名前の変更は「元に戻す」ができる
  （戻すと、元に戻した人の結びつけとして書き直す＝ルール上、他人の名前で書けないため）
- **招待と参加**（`view-join`・`#join=コード`）: ①LINEの中→「Safari・Chromeで開いて参加する」＋参加コード表示 ②未ログイン→「Googleでログインして参加」
  （参加コードを localStorage `mahjong-pending-join` に覚えてからリダイレクト。戻ったら`resumePendingJoin`が自動で参加を続ける）
  ③ログイン済み→自動で参加（ログイン状態が後から分かる場合も onAuthStateChanged で続ける）→仲間ページが開き「名簿のどの人ですか？」を聞く。
  招待の画面には必ず「参加せずに結果だけ見る」を置く
- **仲間ページを削除する機能は無い**（2026-09-29 ユーザー判断。作成者にも出さない。作成者以外は「この仲間ページから抜ける」だけ）
- 参加コードは8文字（大文字・紛らわしい文字なし）。作成者が作り直すと古い招待リンクは使えなくなる（参加済みの人はそのまま）
- **集計**: `circleStats(circle, sessions, mode)`＝名簿の人に結びつけた席だけを数える（ゲスト・未結びつけ・名簿から消えた人の席は数えない）。三麻と四麻は別。
  対戦成績は`h2hAdd`をそのまま使う（keyOf＝席→名簿の人）
- 作成の順番に注意（ルールが前の書き込みを見るため）: 仲間ページ本体 → 作成者のメンバー登録 → 参加コード → 名簿の自分（uid付き）。
  削除は逆に、メンバー → 参加コード → 本体
- **LOGIN_ENABLED が false の間は、仲間ページの作成・参加・追加の入り口を出さない**（閲覧リンクで見ることはできる）

  - **区切り線は画面と同じ3種を描く**: チームの境目（`c.tb`）／先頭列の右（`c.left`）／チーム名行の下（`c.teamRow`）。
    色は見出し行=rgba(255,255,255,.85)・本文=#dfe8e6（CSSのborderはCanvasに反映されないので自前で引く）
  - 試合結果は画面と同じ「スコア＋薄い点数＋チップ差」の縦積み＋合計行
    （セル内の2行目以降は`subs`として9pxで描く。列幅・行高もsubsを含めて計算する）。
    チーム順位はメンバー名をサブ行で表示
- **画像プレビュー**（`openImagePreview`）: カードの「プレビュー」ボタン（`showResultImage`）とまとめ作成は、
  **まず全画面プレビューを開く**（保存せずその場で結果を確認するため）。書き出したCanvasをそのまま表示するので保存物と同一の絵。
  中身: タップで幅フィット⇄等倍のズーム切替、「PDF・印刷」（`printPreviewImage`＝`@media print`で画像だけを紙面に出す。
  スマホの印刷画面から「PDFとして保存」できる）、「保存・共有」（`shareCanvasImage`）。
  画像はblob URLで渡し、閉じるときにrevoke（`img.src=''`はページURLを読みに行くので`removeAttribute`で外す）
- **まとめ画像**（`openComposeModal`→`runCompose`→`buildComposedCanvas`）: 入れる項目をチェックで選び、
  **縦長1枚（幅1080px）**に連結する。ゲーム画面と結果詳細の末尾に「結果をまとめてプレビュー」ボタン。
  各セクションは内側幅に収まるよう縮小して白い角丸カードに載せ、上に見出しを付ける。
  **見出しと白カードは重ねない**: `textBaseline='middle'`なので見出し（15px）はy+12を中心に約y+3〜y+21を占める。
  カードは影（blur6・offsetY2）ぶんも上にはみ出すので、`LABEL_H`はカード上端(y+LABEL_H−CARD_PAD)が
  文字の下端より十分下に来る値にする（**36**。以前は30で約4px重なっていた）
  **iOS Safariのcanvas上限（1辺8000px・総ピクセル数16.7M）を超えるとtoBlobが黙ってnullを返し、保存もプレビューも失敗する**。
  上限対策は`imgCanvas`に集約: **scを省略すると`imgFitScale(w,h)`が上限に収まる倍率を自動で選ぶ**ので、
  表・グラフ・単体出力・まとめ出力のすべてに自動で効く。実倍率は`c._sc`に持たせ、CSSサイズは`imgCssSize(c)`で逆算する
  （`body.width / IMG_SCALE`と決め打ちしてはいけない）。
  倍率の下限は`IMG_MIN_SCALE`=0.7（本文13pxが約9px＝読める限界）。
  **収まらないときの段階的な対処**: ①列が多いほど1列の上限幅を下げる（`COL_MAX`＝27列以上84px／15列以上104px／既定132px。
  40人でも幅8000pxに達しない）②それでも収まらない試合結果は**薄い点数・チップ差を省いた縮約版**で作り直す
  （`roundRowHtml(..., compact)`。行高が約6割になり収容できる試合数が約1.7倍。帯のラベルに「（スコアのみ）」と付く）
  ③それでもダメなら壊れた画像を作らず`IMG_TOO_LARGE`を返し、呼び出し側がCSVを案内する。
  **判定は四捨五入後の実ピクセルで行う**（ぴったり上限になる倍率は丸め誤差で1px超えるため、面積由来の倍率は0.999倍しておく）。
  実測: 16人4チーム100試合＝全項目可（試合結果の文字17px）／40人4チーム100試合＝全項目可（同12px）／
  40人10チーム300試合＝全項目可（同9px）／500試合＝試合結果の単体のみ案内、他は可
- **CSVエクスポート**（「CSV」ボタン→`openCsvModal`→`runCsvExport`→`exportCsv(g, opts)`/`buildCsv(g, opts)`）:
  導線は**画面末尾の「CSVで書き出す」ボタン1か所だけ**（ゲーム画面・結果詳細とも「結果をまとめてプレビュー」の直下）。
  カード上にボタンが並びすぎて見にくくなるため、2026-08-06に試合結果カードの右上から移した。
  見た目は`.auto-btn.sub`（白地＋緑枠／三麻は青。オレンジはCTA限定なので主役の「まとめてプレビュー」とは配色を分ける）。
  表示条件はcompose-btnと同じ＝試合が1件以上（カードの開閉には連動しない）。
  押すと**項目選択モーダル**（`csv-modal`）が開く。選べるのは
  スコア／点数（素点）／チップ／焼き鳥／チョンボ／日時／合計行／グループ情報の8つ。
  **既定は最低限＝スコアと合計行だけON**（`CSV_DEFAULT`）。選択は`mahjong-csv-opts-v1`に記憶し次回も同じ状態で開く。
  チップ/焼き鳥/チョンボは**設定有効または記録ありのときだけ**選択肢に出す（旧データ互換）。
  そのとき出さなかった項目のON/OFFは保存時に書き換えない（`csvItemKeys`にある分だけ更新）。
  値の列が0個なら書き出さず注意を出す。試合番号は常に入る。
  **1人あたりの値列が1つだけのときは見出しを名前だけにする**（「山田 スコア」ではなく「山田」）。
  メタ「ゲーム情報」（ゲーム名/作成日/試合形式/チーム編成※チーム戦のみ）を選ぶと先頭に4行＋空行が付く。
  **UTF-8 BOM付き**（Excel日本語環境の文字化け対策。ソース中のBOMは`﻿`のエスケープ表記で書く=生文字は編集事故のもと）。
  列順は試合結果と同じ（チームA→B…）。不参加は空欄・マークは○。
  ファイル名「まじゃすこ_ゲーム名_YYYYMMDD.csv」（禁止文字は_に置換）。track('csv_export')
- **過去の試合への導線**: ①ヘッダー右上のマイページ（`goMyPage`）・LPの「最近の試合」の下の「マイページで過去の試合をすべて見る ›」
  ②ゲーム画面末尾の「過去の試合・引き継ぎURL ›」（leaveGame→showView('history')）。
  引き継ぎURLカードの発行場所がこの画面なので、導線を絞りすぎない
- **結果詳細からの編集も必ずFirebase（sessions/{id}）へ書く**（2026-08-08。名前編集`saveDetailEdit`・
  試合修正`editDetailRound`・復元`applyRestore`のdetail側）。かつて端末内の控えだけを更新していたため、
  「再開」「最近の試合」「共有URL」などサーバーから取り直す入り口を通ると編集前に巻き戻る不整合があった。
  **データの正は常にsessions側**。書き方は「最新を取得→編集を載せて書く」（fetch-rebase-write）:
  名前編集は最新settingsにplayerNamesだけ差し替えて部分update（メンバー数が変わっていたら中断して最新化）、
  試合修正はシートを開く前に最新roundsへ更新してから編集（古い控えのまま全試合を書き戻すと他の人の新しい試合が消える）。
  サーバーへ書けたときだけ端末の控えも更新（片方だけ更新すると巻き戻り事故が再発する）。
  名前編集は登録名（savePlayerNames）とmylistsのname にも反映
- 過去の試合: カードは**ゲーム名・日付・総試合数・四麻/三麻・個人戦/チーム戦・プレイヤー名のみ**（結果のプレビューは載せない）。
  文字は13pxで統一、グループ名はellipsis・.history-infoにmin-width:0（枠はみ出し防止）。絞り込み=キーワード+四麻/三麻。
  カード右上に「再開」と**「削除」**（`confirmDeleteHistory`→確認モーダル必須→`deleteHistoryItem`）。
  削除で消えるのは**この端末の履歴＋引き継ぎURLの一覧**（mylistsから外さないと次の同期で復活する）＋分類タグのみ。
  **sessions/のデータ本体には触れない**＝仲間の画面には影響せず、共有URLを開けば自分でもまた表示できる（確認文にも明記）。
  確認モーダルのOKボタンは使い回しなので文言「削除する」を毎回セットし直す。
  **削除の同期設計（2026-08-08）**: 削除の影響範囲は
  「この端末の履歴・分類タグ」「引き継ぎURLのリスト（削除印）」「同じ引き継ぎURLを使う自分の別端末（伝播で消える）」のみ。
  **sessions/には触れない＝仲間の端末には一切影響しない**（グループ本体は残り、共有URLでいつでも再表示できる）。
  仕組みは**削除印方式**: `deleteHistoryItem`は`mylists/{id}/groups/{gid}`をremoveせず
  **`{deleted:true, at}`を書く**（数十バイト・コスト無視できる）。
  removeだと別端末が「この端末にだけある新規」と誤解してリストへ書き戻し、削除が復活してしまう。
  `mergeMyListData`は印を見て ①取り込まない ②ローカルの控え・タグも消す（**伝播**）③書き戻さない（myListSynced.add）。
  伝播側にはローカル墓標を付けない＝**リストの印が唯一の権威**（誰かが開き直して印が消えたら次のマージで自然復帰）。
  印の解除は「自分から開き直す」操作で: `joinSession`が`unmarkDeleted`＋`myListSynced.delete`→
  `syncGroupToMyList`のupdateに常に`deleted: null`が入っていて印ごと上書きする。
  **ルール未適用環境へのフォールバック**: 印の書き込みが拒否されたら従来のremoveに退化（壊れない。
  rules.jsonに`deleted`キーを追加済み→コンソール手動反映が必要）。
  ローカル墓標（localStorage `mahjong-deleted-v1`＝gid→削除日時、200件超で古い順に破棄）は
  オフラインで印を書けなかった場合の保険としてtoFetch除外に使う。
  **削除直後の「元に戻す」トースト**（`UNDO_TOAST_DELETE_MS`**4秒**・showUndoToastに関数を渡す形）＝
  控えコピーの復帰＋タグ復帰＋墓標解除＋syncで印も解除（`restoreDeletedHistory`）。
  **対局中グループの削除時は`stopListening()`**（popstateで戻るとリスナーが生きたままになり、
  次のvalueイベントの`saveToLocalHistory`が削除を数秒で巻き戻すため）
- 履歴ログ: フィルタタブ（すべて/入力/修正/削除。タグと同配色=緑/オレンジ/赤）。点数は「名前 点数」ペア表示
- **変更をもとに戻す（端末内バックアップ）**: 削除・修正・設定変更・名前編集の**直前の状態**（name/settings/rounds）を
  localStorage `mahjong-backup-v1` に控える（`takeBackup(g, label, expect)`）。
  **Firebaseには一切書かない**＝保存容量・通信コスト・セキュリティルールは一切変わらない（rules更新も不要）。
  保持は**1グループ5世代・全体900KBまで**（超えたら古いものから捨てる。QuotaExceededでも丸ごと失敗しないよう
  減らして再試行する`writeBackups`）。
  導線は2つ: ①操作直後のトーストの「元に戻す」（`showUndoToast(msg, key, ms)`。`.toast.act`でpointer-eventsを有効化。
  **表示時間は取り返しのつかなさで変える**: 削除・修正・名前更新=`UNDO_TOAST_MS`**8秒**／
  設定の更新=`UNDO_TOAST_SHORT_MS`**3秒**（何度でもやり直せる操作なので短くしてよい。通常のトーストは2.5秒））
  ②履歴モーダル上部の一覧（`backupSectionHtml`。タブより上に置く＝フィルタの対象ではないため）。
  戻すと`sessions/{id}`にname/settings/roundsを書き戻す＝**全員の画面に反映される**。復元自体も直前を控えるのでやり直せる。
  **他の人の入力を巻き戻さないためのガード**: 控えた時点で想定した試合数（`expect`）と現在の試合数が食い違うときは
  即時復元せず確認ダイアログに回す（`restoreBackupById(key, false)` → `confirmRestore`）。履歴からの復元は常に確認あり。
  過去の試合（結果詳細）から戻す場合はlocalStorageの控えを書き換える（行き先の判定は`restoreTargetOf`）
- 設定変更モーダル: 試合形式は変更不可（文言も「試合形式」で統一。対局形式/対戦形式とは書かない）。ルール変更は全再計算（注意のアイコン i-warn を付けて表示）。ヘッダー右に小「キャンセル/保存」（closeFormModalがクリア）。
  メンバー削除は対局済み/最低N人なら不可。チーム戦OFFでもteams保持

### 仲間ページの権限と試合の保護（2026-09-29）
- **見る人**（閲覧リンク #c=・ログイン不要）: 結果を見るだけ。**ログインすれば、名簿で「まだ確認済みでない人」を自分にできる**（`claimCircleMember`・メンバーにはならない。名簿にない名前を足す入口は出さない）。
  自分に結びついた席を「確認済み」にもできる（`confirmMySeats`）。履歴には claim/confirm だけ残せる（`addCircleLog`）。自分を選ぶと、その試合が自分の過去の試合に入る（`syncCircleGamesToMine`）
- **編集メンバー**（招待リンク #join= / 参加コード）: 試合の追加・名前の結びつけ。外せるのは自分が追加した試合だけ（作成者・管理者は全部）
- **試合の結果を守る**: 仲間ページの試合IDは閲覧リンクから誰でも見えるため、確定の期限（lockAt）が無い古い試合には開いたときに「最後の編集から24時間」を書き込む（`lockCircleGames`→`stampLockAt`）。確定後は誰も書き換えられない
- **仲間ページへの追加は24時間で確定**（2026-10-02）: 追加するとき `circles/$cid/games/$sid/lockAt`＝追加から24時間（`addGameToCircle`・`CIRCLE_GAME_FIX_MS`）。
  外せるのはそれまで（`circleGameRemovable`。試合のメニューに「外せるのは M/D hh:mm まで」、過ぎたら「この仲間ページに確定しています（外せません）」。履歴の「元に戻す」も同じ）。
  lockAt の無い古い追加は最初から確定（外せない）。ルールを貼る前は lockAt 付きの追加が拒否されるので、期限なしで入れ直す（＝すぐ確定）
- **試合そのものは誰も消せない**（ルール: sessions/$id の .write に `newData.exists()`。アプリの「削除」は自分の一覧から外すだけ）。確認は `tools/session_delete_rules_test.py`（本番・検証用の試合が1つ残る）
- ルール（database.rules.json）: roster/$mid はログインした人なら「uid が無い人を自分に」「自分の uid を外す」だけ（名前は変えられない）。seats/$seat は結びつけ先が同じまま self:true にするだけ。log は claim/confirm だけ
- **リンクは「仲間のリンク」1本**（2026-09-29 ユーザーの判断。見るリンクと招待リンクの2本はわかりにくい）: 共有シート（`openCircleShare`）は #join=コード のリンクだけ。
  開くと、ログインしていなければ参加の画面を挟まず**そのまま結果**（`openJoin` → `openCircle`・`circleJoinCode` を覚える）と「Googleでログインして参加」（`startCircleJoin`。LINEの中では外のブラウザへの案内＝参加の画面）。
  ログイン済みならそのまま参加（編集メンバー）。ログイン状態があとから分かったときも参加する（onAuthStateChanged）。古い閲覧リンク（#c=）は見る＋自分を選ぶだけ
- 過去の試合の順位のピル: 1位＝金・2位＝青みの銀（#E1E9F1）・3位＝銅、**4位以下は墨色の地に白字**（#4E5654。メダルの淡い地と紛れないように）

- **確認済みのGoogleアカウント**（2026-09-29）: 確認済みにしたとき、名簿に Google の表示名・顔アイコンのURL・日時を残す（roster/$mid の `gname` `gphoto` `gat`。**メールアドレスは残さない**。書けるのはその人を確認済みにした本人だけ＝ルール）。
  「確認済み」の印（`circleBadge(r, mid)`）を押すと `openVerifyInfo`（顔・表示名・日時）。自分なら「確認済みを外す（自分を選び直す）」、作成者・管理者は他の人の確認済みを外せる（`adminUnclaimCircleMember`）。

- **あとから足したメンバー**（2026-09-30）: 仲間ページに入れたあとで試合に足された人の席は、メンバーが仲間ページを開いたときに**名簿の同じ名前の人へ自動で連携**（`bindLaterSeats`。名簿に無い名前は人を増やさず「未連携」のまま＝ゲストにした席と区別できないため）。
